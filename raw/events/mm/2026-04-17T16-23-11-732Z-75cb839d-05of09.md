User: how does gemini get it instructions?

Assistant: Gemini CLI picks up instructions from four places, in order of load:

1. **`~/.gemini/settings.json`** — user-level defaults (model, tool policy, etc.). You already have one.
2. **`GEMINI.md`** at the cwd (and parent dirs, Claude Code style) — project-level system context, auto-loaded. **mm doesn't have one**, so Gemini runs without project framing today.
3. **Installed skills** — agent-behavior defs discoverable via `gemini skills list`. Scoped per-project or user-global.
4. **Initial prompt** — whatever you pass via `-p`, `-i`, or the positional `query`. That's the "user turn," not instructions, but it's the only per-invocation context.

Plus `--include-directories` adds extra workspace roots, and `hooks` are event-driven behavior (not static instructions).

**Practical for mm:** if you want Gemini to understand mm's conventions every time you invoke it from the repo, drop a `GEMINI.md` at the repo root (analog of `CLAUDE.md`). Short-form: what mm is, where `raw/`, `wiki/`, `meta/` live, the source_type/project taxonomy, the citation format. Then `gemini -p "<prompt>"` from the repo root automatically sees it — no more inlining context.
