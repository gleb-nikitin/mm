User: i think we need to injest in batches through -p

Assistant: Right call for automation. Tradeoffs:

- **Interactive** — skill + schema paid once, amortized across many turns (what we just did). Great for human-in-the-loop iteration, bad for unattended operation.
- **Batch `-p`** — each invocation is a fresh session, skill + schema reloaded (~8KB preamble per call). Scriptable, deterministic, safe to run from cron. Right for "process the queue overnight."

The concrete shape is a small `scripts/ingest-batch.ts` that:

1. Reads **N unprocessed raw entries** from the DB (limit configurable, e.g. `--batch 10`).
2. Composes a `gemini -y -p` prompt with `@` references to `meta/skills/ingest.md` + `meta/schema.md` + the N raw files.
3. Spawns gemini via `Bun.spawn`, captures output.
4. Appends the run summary to `meta/log.md`.
5. (Optional) marks the batch's raw entries `processed=1` only if wiki changed — same provenance check `brain process` does today.

Key tuning knobs:
- **Batch size.** Pass 1 used ~3% for one long file. If you keep batches to ~10–15% of context each, you have room for the skill/schema + raw files + tool calls + output. Good default: 10 raws per batch.
- **Group by project.** Batches scoped to one project produce more coherent wiki updates (fewer unrelated subjects competing for attention in the same pass).

Assistant: Good instinct. Git inside `raw/` is the right primitive — and it cleans up two inefficiencies at once:

**1. Batch identity is free.** Commit = "this batch was ingested." Staged = "in flight." Untracked/modified = "pending ingest." The `processed=1` flag in SQLite becomes redundant (or kept as a cache of the git state). Gemini gets told "ingest the staged set" — no ambiguity.

**2. Growing-session diffs.** If we also switch `import-claude.ts` to write a **stable filename per session-id** (`raw/claude/mm/<session-id>.md` instead of a fresh timestamped file each run), re-imports overwrite the same file and **git captures the delta**. Gemini then processes a per-file diff — only the new turns since last ingest — instead of re-reading the whole 341-turn transcript. That's the real token saver for running sessions.

Tradeoffs worth being honest about:

- **Two states if both kept.** DB `processed` flag + git commits. Cleanest is to make git the source of truth and derive the flag from `git log` — one less thing to sync.
- **Raw is "immutable" becomes "append-mostly".** Overwriting a session file for incremental re-imports bends the original invariant. Arguably the right bend: a session is one logical object, and git already enforces the "immutable" part via history.
- **`import-chats.ts` / other importers need to adopt the stable-filename convention** to benefit. Claude Code's JSONL has `sessionId` (uuid) — perfect natural key. Telegram chats can use `<chat-slug>.md`. Docs can use the original filename.
