## Addenda (post-audit, 2026-04-20)

These supersede anything below that conflicts. Read first.

**A1. No destructive deletion in v11.** `wiki/<project>/*.md` and `raw/events/<project>/*.md` stay on disk until v12 (briefing) lands. They become read-only legacy — the tool stops writing them, but does not delete them. Cleanup is a separate pass after the new retrieval surface is proven. The stated concern (retrieval regression) is weak for mm (current pages are test-run output from ~5 sessions), but the pattern matters for other projects; keep the shadow-write discipline.

**A2. Multi-source provenance via junction table.** Replace single `source_raw_id` / `source_event_id` columns on `artifacts` with a separate `artifact_sources(artifact_id, source_raw_id, source_event_id, span_start, span_end)` table. Decisions and how-tos typically crystallize across multiple chunks; retrofitting after rows exist is painful.

**A3. Dedup and idempotency live in core, not in the skill.** `brain artifact batch` enforces idempotency via explicit `idempotency_key` on each artifact (librarian computes + sends). No `artifact list` round-trip required from the skill. Supersession detection is explicit — the librarian emits a `supersede` call when it sees a direct contradiction, rather than the skill guessing.

**A4. Proper DB backup, not `cp`.** `brain backup` uses `PRAGMA wal_checkpoint(TRUNCATE)` + `VACUUM INTO '<target>'`. `cp meta/brain.db meta/brain.db.bk` on a hot WAL DB is a data-loss trap and is retired.

**A5. Filter versioning for virtual chunks.** `chunks_virtual` stores `filter_version INTEGER NOT NULL`. Offsets in `segment_start` / `segment_end` are into the *raw* `raw_events.content`, not the filtered view. `filterMechanical()` is versioned (constant `FILTER_VERSION` in `src/narrative.ts`); changing the filter bumps the version and invalidates cached read-through but does not retroactively shift offsets.

**A6. Raw event text is never destroyed.** Filtering is a read-side projection only. Importers never modify `raw_events.content`. The filter's noise-set is conservative; in addition to the Pass-A/Pass-B rules below, lines matching `/\b(error|Error|ERROR|failed|Failed|traceback|Traceback|exception|Exception)\b/` are always preserved regardless of which tool block they appear in.

**A7. `scripts/import-code.ts` is cut from v11.** Deferred to v11.1. Adding input lanes during a storage migration multiplies failure modes; the owner's primary complaint is session-chunk rot, not missing git context.

**A8. Automatic supersession limited to `correction` type.** The librarian never runs an implicit "find-and-contradict" pass across all types. `brain artifact supersede` remains as an explicit CLI the librarian can invoke when it directly sees a contradiction in the chunk it's processing.

**A9. Audience framing softened.** "Primary user: LLM" stays as design orientation. Strike "The human is an observer" — humans are still the recovery/debug path while the new retrieval surface is unproven.

## Audience and frame

- **Primary user: LLM.** The system exists to serve task-aware context injection into agent sessions. Humans remain the recovery and debug path until the new retrieval surface is proven (see A9).
- **Human-facing surface: external-audience docs only.** `README.md`, `human-how-it-works.md`, and similar entry-point markdown stay hand-written because they address GitHub visitors and new contributors, not the tool.
- **Internal state: DB-first.** New writes land in the DB; existing `raw/events/*.md` and `wiki/<project>/*.md` become read-only legacy (A1). The DB is operational memory for the librarian going forward.

## Problem this plan solves

1. **Librarian per-session token waste.** Current extraction model has the librarian rewriting 9 monolithic `wiki/mm/*.md` files by hand. File-maintenance dominates the token cost; extraction itself is cheap.
2. **Markdown rot under append.** Bullets in `wiki/mm/Future_Tasks.md` etc. have no ID, no status, no supersession path. Cross-references and deduplication break at scale.
3. **No atomic artifacts.** Decisions lose their rejected alternatives. Bugs lose their status. Intents don't exist. Tool errors are invisible.
4. **Code-doc drift.** `human-how-it-works.md`-shaped indexes are re-derived by hand every few days. Wasted reads.
5. **Context injection is coarse.** Current `queryBrain` inlines whole wiki pages. No task-awareness, no precision.

## What this plan deliberately does NOT do

- No migration of existing `wiki/mm/*.md` content into artifact rows. Clean break; old pages become reference, not source. (If valuable, re-extract from chunks in a later pass.)
- No typed-table explosion (`decisions` / `bugs` / `intents` as separate tables). One polymorphic `artifacts` table with `type` free-form. Promote to typed tables later when shapes stabilize on real data.
- No briefing protocol implementation. Schema and emission change first; the query/injection side follows in v12.
- No UI work. Existing `ui/index.html` keeps working as an observation panel; new surfaces are deferred.
- No public release. Stabilization first; external readers later.

## Schema v11 (SQL, concrete)

Drop nothing. Add only.

```sql
-- Artifact rows: polymorphic by `type`, opaque `data` JSON per type.
CREATE TABLE IF NOT EXISTS artifacts (
  id               INTEGER PRIMARY KEY AUTOINCREMENT,
  project          TEXT NOT NULL,
  type             TEXT NOT NULL,                     -- free-form: decision, bug, todo, intent, howto, tool_error, code_doc, correction, user_note, friction, future_idea, stack_decision, ...
  data             TEXT NOT NULL,                     -- JSON object, shape determined by type
  idempotency_key  TEXT NOT NULL,                     -- librarian-computed; batch dedup lives here (A3)
  superseded_by    INTEGER,                           -- self-ref; NULL = active; FK to artifacts(id)
  status           TEXT NOT NULL DEFAULT 'active',    -- active | retired | invalid
  created_at       DATETIME DEFAULT CURRENT_TIMESTAMP,
  updated_at       DATETIME DEFAULT CURRENT_TIMESTAMP,
  FOREIGN KEY (superseded_by) REFERENCES artifacts(id) ON DELETE SET NULL
);
CREATE UNIQUE INDEX IF NOT EXISTS idx_artifacts_idempotency ON artifacts(project, type, idempotency_key);
CREATE INDEX IF NOT EXISTS idx_artifacts_project_type ON artifacts(project, type);
CREATE INDEX IF NOT EXISTS idx_artifacts_status       ON artifacts(status);

-- Provenance junction (A2): many sources per artifact; supports cross-chunk synthesis.
CREATE TABLE IF NOT EXISTS artifact_sources (
  id               INTEGER PRIMARY KEY AUTOINCREMENT,
  artifact_id      INTEGER NOT NULL,
  source_raw_id    INTEGER,                           -- raw_entries.id
  source_event_id  INTEGER,                           -- raw_events.id
  span_start       INTEGER,                           -- optional char offset into source content
  span_end         INTEGER,
  created_at       DATETIME DEFAULT CURRENT_TIMESTAMP,
  FOREIGN KEY (artifact_id)     REFERENCES artifacts(id)   ON DELETE CASCADE,
  FOREIGN KEY (source_raw_id)   REFERENCES raw_entries(id) ON DELETE SET NULL,
  FOREIGN KEY (source_event_id) REFERENCES raw_events(id)  ON DELETE SET NULL
);
CREATE INDEX IF NOT EXISTS idx_artifact_sources_artifact ON artifact_sources(artifact_id);
CREATE INDEX IF NOT EXISTS idx_artifact_sources_raw      ON artifact_sources(source_raw_id);
CREATE INDEX IF NOT EXISTS idx_artifact_sources_event    ON artifact_sources(source_event_id);

-- Artifact FTS: one searchable projection of data JSON + type + project.
CREATE VIRTUAL TABLE IF NOT EXISTS artifacts_fts USING fts5(
  artifact_id UNINDEXED,
  project     UNINDEXED,
  type        UNINDEXED,
  text,
  content=''  -- external content; sync via triggers or in-code
);
```

Version bump: `INSERT OR REPLACE INTO schema_version VALUES (1, 11)`.

**Reasoning for polymorphic-first:** taxonomy is iterating. A single `type` column lets us add new types without DDL; JSON `data` lets us change per-type shape without ALTER. Promote to typed tables once shapes stop changing (3+ sessions with stable extraction).

**Artifact JSON conventions** (agreed shapes for first-pass librarian emission — the executor should implement these as TypeScript types in `src/core.ts`, not as DB constraints):

- `decision`:   `{ statement, rationale, alternatives_rejected: [{option, why_rejected}], area }`
- `stack_decision`: `{ technology, chosen_over: [alt], rationale }`
- `bug`:        `{ symptom, context, severity: 'low'|'medium'|'high', status: 'open'|'fixed'|'wontfix' }` — status also mirrored to artifacts.status for queryability
- `todo`:       `{ statement, effort: 'small'|'medium'|'large', area }`
- `intent`:     `{ statement, horizon: 'session'|'milestone'|'project', alignment_check }`
- `howto`:      `{ problem, steps: [string], verification }`
- `tool_error`: `{ tool, error_message, agent_reasoning, resolution }`
- `code_doc`:   `{ area, summary, components: [{name, role}] }`
- `correction`: `{ previous_belief, corrected_view, source_artifact_id, count, last_seen }`
  - **Special semantics**: before emitting a new `correction`, librarian searches `artifacts WHERE type='correction' AND project=?` for a matching `previous_belief` / `corrected_view`. If found: call `brain artifact bump-correction <id>` (increments `data.count`, updates `data.last_seen`, bumps `updated_at`). If not found: emit new with `count=1`. Rare corrections age out; recurring ones accumulate weight.
  - **Briefing consumer** (v12): corrections with `count >= THRESHOLD` (default 3, configurable) get auto-injected into task-relevant briefings. Librarian's job is to document; briefing logic reads.
- `friction`:   `{ pattern, frequency_estimate, first_seen }`
- `user_note`:  `{ note }` (lowest structure; catch-all)
- `future_idea`: `{ statement, why_interesting }`

Unknown types pass through as-is. Schema doesn't reject.

## Pipeline changes

### 1. Tool filter in chunker

File: `scripts/chunk-events.ts`.

Move filter implementation to `src/narrative.ts` so it can be shared between chunker and `brain chunk read`.

```ts
// src/narrative.ts
export const FILTER_VERSION = 1;
export function filterMechanical(content: string): string { /* ... */ }
```

Two-pass filter:

**Pass A: strip noise (lossy).**
- Lines matching `^\[tool: \w+\]\s*$` and the tool-output block that follows until the next `User:`/`Assistant:` marker **if** the tool is in the noise-set: `Bash`, `Read`, `Glob`, `Grep`, `LS`, `TodoWrite`, `TaskCreate`.
- Standalone shell-output blocks detected by `^\$ ` prefix followed by non-prose lines.
- "Acknowledged", "Sure", "OK", "Done" single-line turns with no content.

**Pass B: compress high-signal tool calls (keep evidence, drop ceremony).**
- `Edit` / `Write` tool calls: keep the diff or new-file body, drop the tool-call JSON envelope. Prefix with `[code-change: <file>]`.
- `Agent` / task launches: keep the prompt (that's the intent); drop the task result dump.

**Pass C (A6 — error preservation):**
- Any line matching `/\b(error|Error|ERROR|failed|Failed|traceback|Traceback|exception|Exception)\b/` is preserved regardless of which tool block it appears in. Applied last so Pass A cannot strip it.

Raw `raw_events.content` is never mutated — filter runs read-side only.

Target reduction: ~50% chunk size on typical mm chunks. Verify with `--dry-run` before shipping.

### 2. Git-log importer — deferred (A7)

`scripts/import-code.ts` is cut from v11. Ship v11 validating artifact extraction quality on session chunks first; add the code-delta lane in v11.1 once extraction shape is stable.

### 3. Virtual chunks — chunker becomes a query, not a writer

Rewrite `scripts/chunk-events.ts` emission path:
- Still splits `raw_events` content into turn-aligned ~12KB windows. Same algorithm.
- Does NOT write to `raw/events/<project>/*.md`.
- Instead, emits chunk metadata rows into a new table `chunks_virtual` (or extends existing `chunks` table — check and decide during execution):

```sql
CREATE TABLE IF NOT EXISTS chunks_virtual (
  id              INTEGER PRIMARY KEY AUTOINCREMENT,
  project         TEXT NOT NULL,
  source_event_id INTEGER NOT NULL,
  chunk_index     INTEGER NOT NULL,
  chunk_total     INTEGER NOT NULL,
  segment_start   INTEGER NOT NULL,   -- char offset into raw_events.content (raw, not filtered — A5)
  segment_end     INTEGER NOT NULL,
  filter_version  INTEGER NOT NULL,   -- bumps when filterMechanical() semantics change (A5)
  processed       INTEGER DEFAULT 0,  -- librarian consumed this chunk
  created_at      DATETIME DEFAULT CURRENT_TIMESTAMP,
  FOREIGN KEY (source_event_id) REFERENCES raw_events(id) ON DELETE CASCADE
);
CREATE INDEX IF NOT EXISTS idx_chunks_virtual_project_processed ON chunks_virtual(project, processed);
CREATE INDEX IF NOT EXISTS idx_chunks_virtual_source_event       ON chunks_virtual(source_event_id);
```

Rendering: `bun run brain chunk read <id>` slices `raw_events.content[segment_start:segment_end]` and re-applies `filterMechanical()` at current `FILTER_VERSION`. Offsets index raw text, so filter changes don't invalidate them (A5, A6).

`raw/events/<project>/*.md` is not deleted in v11 (A1) — the chunker stops emitting new files, existing files stay as read-only legacy.

## CLI surface

### `brain artifact batch`

Accepts JSON on stdin, one array of objects. Each artifact carries an explicit `idempotency_key` (librarian-computed, stable across re-runs on the same chunk) and a `sources` array (A2, A3):

```json
[
  {
    "type": "decision",
    "project": "mm",
    "idempotency_key": "decision:mm:chunks-virtual-only-v1",
    "sources": [
      {"source_event_id": 42, "span_start": 1024, "span_end": 3072},
      {"source_raw_id": 117}
    ],
    "data": {
      "statement": "Move chunks to virtual only",
      "rationale": "Markdown rot + per-session token waste",
      "alternatives_rejected": [
        {"option": "keep both", "why_rejected": "doubles storage + git noise"}
      ],
      "area": "architecture"
    }
  }
]
```

Returns: JSON array of `{id, created}` per artifact. Upsert by `(project, type, idempotency_key)`: if the key already exists, returns the existing id with `created: false`; otherwise inserts and returns `created: true`. No round-trip `artifact list` from the skill side. `sources` rows are appended on insert and on upsert (so re-seeing the same artifact from a second chunk adds a source row without duplicating the artifact).

### `brain artifact list`

`brain artifact list --type decision --project mm --status active` — queryable by the librarian for supersession checks.

### `brain artifact supersede <old-id> <new-id>`

Sets `artifacts.superseded_by = new-id`, `status = 'retired'` on the old row.

### `brain artifact bump-correction <id>`

Increments `data.count` and sets `data.last_seen` on a `correction` artifact. Used by the librarian when it re-observes a pattern an existing correction already names — instead of creating a duplicate row. See `correction` type semantics above.

### `brain chunk read <id>`

Reconstructs chunk content from `chunks_virtual` + `raw_events`. Reapplies `filterMechanical()`. This is what the librarian calls instead of `brain read-raw`.

### `brain chunk queue`

Lists `chunks_virtual WHERE processed = 0 AND project = ?`.

### `brain chunk mark-processed <id>`

Sets `chunks_virtual.processed = 1`.

### `brain export --to md`

Regenerates `wiki/<project>/<Type>.md` from `artifacts WHERE type=? AND project=?` for external-readable snapshot. On-demand, not continuous. Used before public release, forks, or manual review — not by the tool itself.

### `brain backup`

Safe hot-DB backup (A4). Runs `PRAGMA wal_checkpoint(TRUNCATE)` then `VACUUM INTO '<target>'`. Default target: `meta/brain.db.bk` (overwritten). `--target <path>` for named snapshots (e.g. `meta/brain.db.pre-v11-bk`). Called from `process-new.command` and anywhere else we want a checkpoint. Never `cp` a hot WAL DB.

## Ingest skill rewrite

File: `meta/skills/ingest.md`.

Rewrite around: "read one chunk, emit one artifact batch."

Core shape of the new skill:

1. Call `brain chunk read <id>` to get filtered chunk content.
2. Scan for signal across known types (the list from Artifact JSON conventions above).
3. For each candidate artifact, compute a stable `idempotency_key` (e.g. `decision:<project>:<slug-of-statement>`) so re-running the same chunk converges on the same row (A3).
4. Emit ONE call to `brain artifact batch` with the full set of artifacts. Core-side upsert handles dedup — the skill does NOT call `artifact list` first (A3).
5. **Explicit supersession only** (A8): if the chunk itself shows a direct contradiction with a known active artifact ("we previously decided X, but now…"), emit a separate `brain artifact supersede <old-id> <new-id>` call. Do not scan for implicit contradictions across the artifact table.
6. **Corrections**: before emitting a new `correction`, check for an existing match on `previous_belief` / `corrected_view` via `brain artifact list --type correction --project mm`. If matched, call `brain artifact bump-correction <id>` instead of creating a duplicate. Rare corrections age out; recurring ones accumulate weight (injected into briefings in v12).
7. `brain chunk mark-processed <id>`.

No file I/O. No monolithic wiki page updates. One read, one batched DB write, done.

Token budget per chunk: target ≤5% of the session window. Current extraction model uses ~15%, most of it on markdown formatting.

## Migration step (one-time, during execution)

No destructive deletes in v11 (A1). Shadow-write: new pipeline emits artifacts + `chunks_virtual` rows; old `raw/events/*.md` and `wiki/<project>/*.md` stay on disk as read-only legacy and can be deleted in a separate pass once v12 retrieval is proven.

1. Snapshot: `bun run brain backup --target meta/brain.db.pre-v11-bk` (WAL checkpoint + VACUUM INTO, A4).
2. Run schema migration via `initDb()` — bumps `schema_version` to 11 and adds new tables.
3. Reset the old chunking flag so existing `raw_events` rows re-chunk into `chunks_virtual`: `UPDATE raw_events SET chunked=0 WHERE project='mm'`. Do NOT delete the `raw/events/<project>/*.md` files or their `raw_entries` rows.
4. Rerun the chunker (`bun scripts/chunk-events.ts --project mm`) — produces `chunks_virtual` rows only, no new files.
5. Run librarian against the `chunks_virtual` queue. This is the first-pass validation of the new pipeline on real data.

Rollback: `bun run brain backup --target` created `meta/brain.db.pre-v11-bk`; restore by stopping the tool, `cp meta/brain.db.pre-v11-bk meta/brain.db` (safe because the snapshot was made via VACUUM INTO, not a hot copy), reverting the commit. Legacy `raw/events/*.md` and `wiki/*.md` files are untouched by the migration, so no restore is needed for them.

## Resolved decisions (post-audit)

1. **`brain export --to md`: on-demand only.** Do not auto-run after librarian passes — reintroduces the noise v11 kills.
2. **Separate `chunks_virtual` table.** Keep existing `chunks` for embedding-bearing search units; `chunks_virtual` is narrative-process state. Different semantics, different table.
3. **Dedup in core, not skill (A3).** `brain artifact batch` upserts by `(project, type, idempotency_key)`. No `artifact list` round-trip from the skill.
4. **Explicit `idempotency_key` (A3).** Librarian-computed stable key per artifact. Canonical-JSON hashes rot as per-type shapes evolve; explicit keys don't.
5. **Old `wiki/mm/*.md`: stay on disk (A1).** Read-only legacy. Not archived into a tarball; not deleted. Git history covers deeper rollback. Deletion is a separate pass after v12.
